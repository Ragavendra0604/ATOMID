POS Hardware Integration Architecture

This document details the hardware integration layer for the offline-first Flutter POS application.

Goal: Decouple physical peripheral connections from business logic while maintaining the OFFLINE-FIRST → ONLINE SYNC transaction reliability guarantees.

1. Supported Hardware

Device Type Protocol/Connection Notes
iBall BSS209 Barcode Scanner Keyboard HID Intercepted globally via FocusNode and timestamp debouncing.
RETSOL RTP-81 Receipt Printer System Print Spooler (PDF) Requires OS driver. App generates thermal PDF and routes to spooler natively.
TVS Electronics LP 46 DLITE Label Printer System Print Spooler (PDF) Configurable profiles (50x35mm, 50x50mm).

2. Architecture: Hardware Abstraction Layer (HAL)

The system interacts with peripherals through the HAL rather than embedding native plugins into UI code.

  • HardwareManager: Registry for all connected devices.
  • BarcodeScannerService: Emits a stream of decoded barcodes.
  • ReceiptPrinterService & LabelPrinterService: Receives pre-rendered PDF bytes and transmits them to the configured spooler asynchronously.
  • PrintJobManager: Protects against duplicate document prints resulting from UI rapid-tapping or background sync retries.
  • GlobalBarcodeListener: A global Flutter widget that wraps the app shell, trapping rapid keystrokes to differentiate hardware scanners from slow human typing.

3. Transaction Safety (Offline-First Rules)

CRITICAL: A hardware failure MUST NEVER cause data loss or roll back a completed local transaction.

When a sale is completed, the transaction is saved to the local Hive database and placed into the Sync Queue. Only after successful database persistence is the print job dispatched.

If the printer is disconnected or out of paper, the PrintJobManager marks the print as FAILED. The sale itself remains completely valid, inventory is deducted, and the transaction will sync to Firebase once online. The cashier can manually reprint the receipt.

4. Hardware Configuration

Hardware configuration is specific to each terminal/device. The app persists selections locally in hardware_config via a raw Hive Box. This allows Till A to use Printer X while Till B uses Printer Y without conflicting settings.

Configured via: HardwareSettingsScreen.

5. TVS Electronics LP 46 DLITE Direct Label Printing Architecture

The Windows "Add a device" Error Explained

Previously, the application relied on the interactive Printing.layoutPdf() flow, which passes the generated PDF to the native Windows OS print spooler UI. If the host machine has zero printers installed (not even virtual printers like "Microsoft Print to PDF"), Windows intercepts the call and forces a generic "Before you can perform printer-related tasks... you need to install a printer" error dialog, blocking the app entirely.

Previous Flow vs New Direct-Print Flow

Previous Flow (Interactive):

Bulk Generator UI → Generate A4 Sheet PDF → Printing.layoutPdf() → Windows OS Dialog → Select Printer → Print

New Flow (Direct/Silent):

Bulk Generator UI → LabelTemplateEngine (Exact mm sizing) → LabelDocument → PrintJobManager (Duplicate Protection) → LabelPrinterService → WindowsPdfLabelPrinterAdapter → Windows Spooler → TVS LP 46 DLITE

The new flow uses the selected hardware configuration to bypass the OS dialog, submitting the print job silently. This is achieved using package:printing's directPrintPdf capabilities, wrapped inside our WindowsPdfLabelPrinterAdapter.

Label Generation & Configurations

Instead of generating a standard A4/Letter sheet of labels (which would scale incorrectly and squish onto a single TVS label), the ExportService.generateBulkLabelRollPdf() method constructs a continuous PDF where every individual page precisely matches the physical label dimensions. The adapter respects two primary configurations:

  • 50 × 35 mm: Standard price tag, aggressively scales text down to fit vertical bounds.
  • 50 × 50 mm: Square price tag format with more vertical breathing room.

Failure Handling, Retry, and Protection

The PrintJobManager prevents multiple background or accidental rapid-tap submissions of the exact same label sequence. If the TVS printer is disconnected (or driver missing), the WindowsPdfLabelPrinterAdapter instantly detects the failure. The LabelPrinterService marks the hardware status as DeviceStatus.error and fails the job without crashing the application. Crucially, the business data (the created products/variants) remains completely intact, and the user is free to retry once hardware is restored.

UNKNOWN — REQUIRES PHYSICAL HARDWARE VERIFICATION

The following aspects of the TVS LP 46 DLITE could not be fully tested in the development environment because the physical printer was not connected (only "Microsoft Print to PDF" was available to the OS spooler during development). They must be verified on the actual hardware:

  • Actual Connection Method & Driver Discovery: The exact driver name installed by Windows when the TVS LP 46 is plugged in via USB.
  • Physical Margins & Padding: Whether the TVS driver injects its own hardware margins that might crop the perfectly sized 50x35mm PDF.
  • Label Gap / Tear-off Alignment: How the spooler pages align with the physical roll gaps between consecutive tags in bulk printing.
  • Print Density / Quality: Readability of the scaled-down barcode strings at 203 DPI.
