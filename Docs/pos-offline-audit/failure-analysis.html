Failure Scenarios & Resilience Matrix

Scenario Detection Current Behavior Data Risk
Internet loss during Sale Connection state listener Sale successfully writes locally and stays in SyncQueueBox. None
Application crash mid-Sale Restart checkout validation The checkoutJournalBox is meant to act as a WAL. Any sale caught partially committed without being removed from the WAL can theoretically trigger recovery, though manual undo stack heavily relies on memory. Low/Medium
Sync Request drops ACK Timeout / Firebase SDK Error Client retries operation. Firestore merge: true with explicit absolute UUIDs makes this completely idempotent. No duplicates generated. None
Permanent Sync Failure Retry counter hits 5 Queue item moved to DEAD state. UI shows failure. Operator can use "retry failed" action. None
Device stolen offline Physical Local Hive DB is unencrypted. Complete customer ledgers and product catalogs are exposed on-device. Critical

Authentication Resilience

Because Firebase Auth caches session tokens, the user remains authenticated while offline until the token explicitly expires. There is a risk that if an authentication token expires during a prolonged offline period, the POS terminal could be locked out of syncing (throwing permission-denied) until the user signs back in.

Sync Process Crash Recovery

If the app crashes while the SyncService is in the middle of uploading a batch, the items may be stuck in the SYNCING state permanently (since it's an in-memory flag mapped to the DB). However, storage_repository.dart contains a resetStuckSyncItems() function which safely reverts SYNCING items back to PENDING on app startup.
