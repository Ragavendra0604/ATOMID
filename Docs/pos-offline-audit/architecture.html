System Architecture

Overview

The system is a fully distributed offline-first POS application using Flutter, Hive CE, and Firebase. It does not follow a traditional "Frontend → API → Database" model. Instead, every POS terminal functions as an independent, fully-capable node that commits transactions entirely locally first.

Data Ownership & Source of Truth

Entity Offline Writable Sync Direction Source of Truth
Product Yes Bidirectional Pending local queue, then Server
Sale Yes Local → Server Local Device (Source)
Inventory Yes Bidirectional Server (but overwritten by last-writer)
Customer Yes Bidirectional Pending local queue, then Server

Offline Transaction Flow Trace

Cashier
  ↓
Add Product (UI: Cart state updated)
  ↓
Complete Sale (SaleService.checkout)
  ↓
Generate offline Invoice Number (INV-YYYYMMDD-[DeviceID]-0001)
  ↓
Deduct Inventory Locally (StorageRepository.performStockOut)
  ↓
Save Sale (Hive: salesBox)
  ↓
Add to Sync Queue (Hive: syncQueueBox, Status: PENDING)
  ↓
Internet Disconnected: Queue remains pending in Hive indefinitely until reconnection.
