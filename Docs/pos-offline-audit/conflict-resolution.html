Conflict Detection & Resolution

Strategy: Last-Write-Wins (LWW)

The system utilizes a time-based Last-Write-Wins strategy without strict vector clocks or conflict resolution merging (aside from standard Firestore SetOptions(merge: true) semantics). Conflict resolution happens exclusively during the Pull phase (applyRemote).

Pending Local Overrides

In storage_repository.dart (applyRemote), if an entity being pulled from the server currently has an unsent operation in the local SyncQueueBox, the remote pull is completely ignored for that entity. Local pending changes are considered the absolute source of truth.

Idempotency

Operations are highly idempotent because:

  1. Transactions (Sales/Purchases) are allocated unique UUIDs (Ids.generate()) before they even reach the sync queue.
  2. Firestore uses batch.set() with absolute UUID paths, meaning if a request drops its ACK and the client retries, Firestore safely overwrites the exact same data without duplicating the Sale.

Inventory Conflict Risks (Overselling)

Inventory counts represent the biggest conflict risk.

POS A sells Product X (Qty -1)
POS B sells Product X (Qty -1)
Both are offline.

When selling, performStockOut directly subtracts the quantity from the Product entity and enqueues the entire product entity for sync. Because the system uses Last-Write-Wins for the entire document:

  • POS A syncs: Server product quantity is updated to N-1.
  • POS B syncs: Server product quantity is overwritten to N-1 (it ignores POS A's change because it sends its absolute locally calculated value).

The correct stock should be N-2. This architecture causes silent inventory overwrites across multiple terminals.

Invoice Number Collision Prevention

Because sales are created offline, generating invoice numbers safely is critical. The system solves this elegantly by embedding a Device Short Code into the offline-generated invoice sequence:

INV-20260810-A3F1-0001

Because A3F1 is unique to POS Terminal A, Terminal B will generate INV-20260810-B9Z4-0001, completely eliminating offline invoice number collisions.
