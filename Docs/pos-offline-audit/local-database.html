Local Database Architecture

The system relies heavily on Hive CE, a fast, synchronous, key-value NoSQL database for Dart/Flutter. Because the system is truly offline-first, Hive acts as the primary data store, not just a cache.

Database Schema & Boxes

Data is separated into distinct "Boxes" managed inside StorageRepository. Key boxes include:

  • products, customers, suppliers
  • sales, purchases, expenses
  • customer_ledgers, supplier_ledgers
  • sync_queue, sync_logs
  • checkout_journal (Write-Ahead Log for crash recovery)

Memory Indexing

To provide instant search capability (e.g., scanning barcodes or typing phone numbers) without repeatedly querying disk, StorageRepository maintains in-memory maps synchronized with Hive data:

// Fast index for barcode -> Product
final Map<String, Product> _barcodeIndex = {};

// Mobile number -> Customer
final Map<String, Customer> _mobileIndex = {};

Transactions & Safety

Hive CE does not support atomic cross-box transactions natively. To prevent partial writes or data corruption during complex workflows (like checking out a cart which affects Sales, Products, Customers, and SyncQueues), the system utilizes an application-level rollback mechanism:

Manual Reversals (Undo Stack)

In SaleService.checkout, operations are pushed to an undo array of async functions. If any step fails (e.g., throwing an error before the checkout is completely finalized), the system walks backwards through the undo stack and reverses the stock movements, ledger entries, and deletes the sale record.
